# REQ-001: 全局通用需求中枢服务 (Universal Bot-to-Issue Hub)

- **版本**: v1.0
- **状态**: baselined -> ready-for-dev
- **负责人**: michmingcao
- **适用场景**: 微信 ClawBot (iLink) / 企业微信 AI BOT 接入 -> 引导提单 -> 自动派发至特定 GitHub 仓库

---

## 1. 客户底层痛点 (Core Pain Points)
1. 需求来源碎片化：客户和业务负责人习惯在微信里发语音、截图、碎片化文字，经常“说过就忘”，缺乏正规工单转化闭环。
2. 缺乏专业产品梳理：客户表达往往只说现象不说背景，研发收到后无法直接执行，反复沟通成本高。
3. 跨系统多项目无法复用：每一个新项目都要重复开发一套对接后台，缺乏统一轻量通用中枢。

---

## 2. 最小可行闭环范围 (Scope & Non-Goals)
### 目标范围 (In Scope)
- **微信 ClawBot 腾讯官方正规渠道**：
  - 官方二维码扫码授权绑定（免封号，零破解）；
  - 0.1秒级输入态通知（“对方正在输入...”）；
  - 多模态处理：支持文字、语音、图片、视频；
  - 支持消息引用与撤回感知。
- **智能产品经理引导 (Cloud AI Conversational Guide)**：
  - 兼容标准 OpenAI 协议（支持 DeepSeek、Qwen、GLM 等主流云端模型）；
  - 交互式提问：澄清用户场景、核心痛点、验收标准；
  - 生成 Issue 预览卡片，等待用户拍板确认后再触发提单。
- **多项目动态路由 (Multi-Repo Routing)**：
  - 支持将不同 Bot / 租户 / 快捷指令分流投递到指定的任意 GitHub 仓库（不限于个人仓库）。
- **企业微信 AI BOT 平滑演进**：
  - 提供统一抽象通道接口 `BaseChannel`，预留企微 Webhook 适配器。
- **代码仓库归属**：
  - 本项目托管于个人仓库 `michmingcao/bot2issue`。

### 非目标 (Non-Goals)
- 本期不构建复杂的第三方 OAuth 计费中心（遵循奥卡姆剃刀，轻量极速交付）；
- 不做多余重型前端框架，采用无依赖原生轻奢 UI 直出扫码与日志大盘。

---

## 3. 核心大白话业务场景 (User Stories)
1. **扫码上线**：管理员打开本地服务页面，手机微信扫码一次，即在微信通讯录拥有“专属需求助手”。
2. **随性表达**：用户在微信发文字或截图“客户说这个商品详情页图片加载太慢，希望能加个骨架屏”。
3. **AI 主动引导**：AI 管家立即回复并进入追问：“收到！请问这个慢主要是在弱网移动端出现，还是所有设备都慢？预期加载时间控制在多少秒内？”
4. **生成草案与拍板**：用户回答后，AI 整理出结构化 Markdown 预览，提示用户回复「确认」。
5. **秒级建单**：用户在微信回复「确认」，AI 秒级调用 GitHub API 在对应的特定仓库创建 Issue，并将 Issue 链接与摘要卡片推回微信！

---

## 4. 回滚与安全预案 (Safety & Rollback)
1. **零密码硬编码**：所有 API Key、GitHub Token 严格通过环境变量或 `.env` 注入，杜绝明文泄露。
2. **防手抖撤销机制**：支持微信端 2 分钟内撤回识别。
3. **Git 一键原子回退**：每次更新具备明确 commit 记录，支持随时一键回滚。
